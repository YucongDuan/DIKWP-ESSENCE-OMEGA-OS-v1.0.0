# Architecture

## 1. Runtime state

A run is represented by

\[
\Omega_t=(\mathcal W,\mathcal T,\mathcal E_t,\mathcal A_t,\mathcal L_t,\mathcal R_t,\mathcal P_t),
\]

where:

- \(\mathcal W\) is the declared world family;
- \(\mathcal T\) is the test and transformation family;
- \(\mathcal E_t\) is the current essence-candidate lattice;
- \(\mathcal A_t\) is the ablation and counterfactual record;
- \(\mathcal L_t\) is the append-only evidence ledger;
- \(\mathcal R_t\) is the typed residual frontier;
- \(\mathcal P_t\) is the purpose, permission, and causal handoff contract.

## 2. Ten-stage pipeline

1. contract registration;
2. world-family registration;
3. candidate-family registration;
4. falsification and ablation;
5. essence-lattice construction;
6. safe reality-probe planning;
7. DIKWP semantic regeneration;
8. residual-frontier registration;
9. causal handoff;
10. bounded certificate issuance.

Every stage enters a deterministic SHA-256 chain.

## 3. Separation of ledgers

The runtime separates:

- observational fit;
- causal necessity;
- cross-world transport;
- reverse regeneration;
- normative admissibility;
- permission and action authority;
- ontological and phenomenal claims.

No axis compensates for failure on another axis.

## 4. Essence lattice

The lattice exposes four relations:

- `component_subset`;
- `observationally_equivalent`;
- `successor/split_after_counterexample`;
- `pareto_dominates`.

A single winner is not forced when two non-isomorphic minimal candidates remain observationally equivalent.

## 5. DIKWP role network

D registers replayable sameness; I registers consequential difference and residuals; K registers bounded local completion; W makes value, harm, permission, and forbidden inference operational; P maps declared inputs to outputs and successor probes. All twenty-five route kinds remain available, while each actual route must name a source record, target record, and generated content.
